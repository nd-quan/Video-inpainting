# BG56 RAFT student at 512x512, initialized from step 7500

Run directory:
`/user/Cilab/Quan/experiment/train_v7_raft_student_sfu_bg56_512_from7500`

The source is `examples/brushnet/dataset/sfu_train_test_80_20/bg56`.
All 4,824 source training frames are training data (4,810 adjacent pairs).
The 1,206 source test frames are validation data (1,192 adjacent pairs).
The staged `dataset/train` and `dataset/valid` are directory symlinks to those
source splits; the manifest preserves original frame IDs and prevents pairs
from crossing splits or sequences. Validation is sampled at eight pairs per
sequence (112 total) every 250 optimizer steps.

Both teacher clean-GT input and student degraded-RGB input use Pillow bilinear
resize to exactly 512x512, with float32 normalization `uint8 /127.5 -1`.
Source ROI masks use nearest resize; internal masks have one on background.
New teacher labels are computed with the original ProPainter
`weights/raft-things.pth`, 20 iterations in both directions, plus
forward/backward consistency validity masks. All 6,002 labels are checked for
shape, dtype, finite values, and valid-mask range before training. A sample
from every branch in both splits verifies that the teacher and student RGB
preprocessing produces exactly equal tensors on the same image.

Student weights are initialized from:
`experiments/train_v7_raft_student_flow_constant_from4750/checkpoint-0007500`.
The optimizer and scheduler start fresh. No artifacts from the BG56 max960
experiment are used. The train target is 4,000 new optimizer steps, AdamW at
constant 1e-5, fp16, frozen BatchNorm, all-region iterative supervision with
gamma 0.8, and loss weights teacher=1, FB=0.1, smoothness=0.01. Checkpoints
include optimizer, scheduler, scaler and RNG state every 250 steps. All 16
scheduled checkpoints fit within the retention limit of 20. `best.json` uses
the lowest validation BG EPE and preserves historical best selection after
resume.

## Start

From the BrushNet repository, using the `guided_diff` Python:

```bash
/home/cilab/ndquan/envs/guided_diff/bin/python \
  examples/brushnet/proposed/STC_encoder_v7_raft_flow_distillation/run_bg56_student_512.py \
  --gpus 1 3 4 5
```

The launcher builds missing teachers, audits the complete cache, tries a
two-step RAFT backward memory probe at batch 4 (then 2 or 1 if needed), reserves
four GiB for DDP overhead, and saves its choice in `batch_config.json`.
Accumulation is initially one. The resulting effective global batch remains
fixed across later resumes. A small fp16 Accelerator test saves full state on
four GPUs and restores it on two, checking weights, AdamW step and scheduler
before launching the real student.

## Pause at a completed checkpoint

In a separate terminal:

```bash
/home/cilab/ndquan/envs/guided_diff/bin/python \
  examples/brushnet/proposed/STC_encoder_v7_raft_flow_distillation/run_bg56_student_512.py \
  --request-pause
```

The request is a file in the run directory. During training, every rank exits
after the next complete checkpoint; `status.json` becomes `paused`. During
teacher generation, generation finishes and the launcher pauses before
student training. Wait for the paused status before resuming. An immediate
process kill can only recover progress present in the latest complete
checkpoint.

## Resume on two GPUs

After the original supervisor has exited, choose two idle physical GPUs:

```bash
/home/cilab/ndquan/envs/guided_diff/bin/python \
  examples/brushnet/proposed/STC_encoder_v7_raft_flow_distillation/run_bg56_student_512.py \
  --resume --gpus 1 3
```

For initial batch 4 on four GPUs, two GPUs use batch 4 and accumulation 2,
preserving global batch 16. If probing selects batch 2, the corresponding
global batch is 8 and the two-GPU resume uses batch 2 and accumulation 2.
The optimizer-step target stays 4,000 and the learning rate stays 1e-5.
The optimizer/scaler/scheduler/model state is restored from `student/latest`.
The shuffled data-loader position is not checkpointed by the existing
trainer, so resumed sample order is not guaranteed to match an uninterrupted
run bit for bit, especially after a change in GPU count.

## Monitoring and outputs

- `status.json`: current phase, child PIDs, cache count, training/checkpoint step.
- `logs/supervisor.log`: preparation and phase transitions.
- `logs/teacher_gpu*.log`: independent teacher generation on each GPU.
- `logs/batch_probe_*.log`: real student forward/backward memory checks.
- `probes/resume_topology/resumed_2gpu.json`: four-to-two GPU resume check.
- `preflight_audit.json`: cache, input shape and RGB preprocessing verification.
- `runtime_config.json` and `runtime_history/`: GPU/batch/accumulation per run.
- `student/initial_validation.json`: step-7500 weights on BG56 before finetuning.
- `student/checkpoint-*/`: full training states and portable RAFT weights.
- `student/best.json` and `student/latest.json`: selected and latest checkpoints.
- `scripts/`: copies of the exact preparation/training code used by the run.

Source file sizes and nanosecond modification times are frozen in
`source_inventory.json`; changes cause the launcher to stop before training
or resume. A supervisor lock prevents duplicate launches into this run.
